# Redis в проекте Max Bots Django

Redis выполняет роль высокопроизводительного связующего звена между компонентами системы. В данной архитектуре он используется для четырех основных задач:

## 1. Брокер сообщений для Celery
Redis служит очередью задач. Когда Django инициирует отправку сообщения (по расписанию или через кнопку «Запустить сейчас»), он помещает задачу в Redis. Контейнеры `celery_worker` постоянно считывают эти задачи из Redis и исполняют их.

## 2. Хранилище результатов (Backend)
После выполнения задачи Celery записывает статус (успех/ошибка) и результат обратно в Redis. Это позволяет отслеживать состояние задач через Django Admin или Flower.

## 3. Распределенные блокировки (Distributed Locking)
Для предотвращения одновременного запуска одного и того же расписания используется механизм блокировок в Redis.
- Перед запуском задача создает ключ `lock:schedule:<ID>` с ограниченным временем жизни.
- Если ключ уже существует, вторая задача завершается, не начиная работу.
- Это защищает от дублирования сообщений в один и тот же чат.

## 4. Хранение сессий и Кэширование
- **Сессии**: Все сессии пользователей Django хранятся в Redis (`SESSION_ENGINE`). Это обеспечивает быстрый доступ и сохранность авторизации при перезагрузке контейнера `web`.
- **Кэш**: Используется стандартный кэш Django для хранения временных данных, что снижает нагрузку на основную базу данных PostgreSQL.

## Технические детали
- **Порт**: 6379
- **БД 0**: Используется для Celery (Broker & Backend)
- **БД 1**: Используется для сессий и кэша Django
- **Persistence**: Включен режим `appendonly yes` для сохранения данных на диске.
